# Pet Game — Developer Handoff

React + TypeScript mini-game frontend (Feed, Walk, Spa). This bundle is for backend engineers integrating **user accounts** and the existing Gamify APIs.

## Quick start

```bash
cd pet-game
npm ci
npm run dev
```

Open the URL Vite prints (default `http://localhost:5173`). Use `npm run build` before deploying static assets.

**Node.js 20 LTS** recommended.

## Backend integration (user accounts)

The frontend currently works **standalone** using `localStorage` for cumulative points. When you add user accounts, the **server should become the source of truth** for scores and game state.

### API endpoints already called

| Endpoint | Used in | Purpose |
|----------|---------|---------|
| `GET /3Care/GamifyPetGameState.do` | `src/App.tsx` | Load user game state on start |
| `GET /3Care/GamifyPetGameAcquirePoint.do` | `src/App.tsx` | Submit points after each mini-game |
| `GET /3Care/GamifyRemovePoop.do` | `src/pages/Home.tsx` | Home poop cleanup reward |
| `GET /3Care/GamifyChangeConfig.do` | `src/App.tsx` | Pet name change |

Common query param: `campaignID=pet_game` (from `gameConfig.campaignID`).

### Acquire-point params (walk game bonus example)

```
campaignID=pet_game
name=walk_game          # feed_game | walk_game | spa_game
point=<base score>
satisfaction=5
bonus=<optional bonus>  # walk friend path only
```

### Server fields the frontend expects

See `src/utils/gameRewards.ts` for merge logic. Authoritative total:

- `totalPoint` — cumulative points (cap at **9,999,999,999** — see `gameConfig.backendMaxTotalPoints`)
- `satisfaction`, `game1PlayTimes`, `game2PlayTimes`, `game3PlayTimes`, daily complete flags

### localStorage to replace with user account data

| Key | File | Notes |
|-----|------|-------|
| `pet_game_scores` | `src/utils/pointsLedger.ts` | `{ feedPoints, walkPoints, spaPoints }` — interim cumulative ledger |
| `lang` | `src/hooks/useLanguage.ts` | UI language (`eng` / `chi`) |

**Integration path:** After login, hydrate state from `GamifyPetGameState.do` instead of `localStorage`. On `acquirePoint`, persist on server first (or in parallel), then update UI from API `totalPoint`. `recordGameScore` in `pointsLedger.ts` can be removed or reduced to a short-lived cache once the API is authoritative.

### Key files to touch for backend work

1. `src/App.tsx` — `fetchGameState`, `acquirePoint`, auth headers / session
2. `src/utils/gameRewards.ts` — API response merging
3. `src/utils/pointsLedger.ts` — replace or gate localStorage when user is logged in
4. `src/config/gameConfig.tsx` — campaign ID, max points, reward tuning

### Dev-only tools (safe to ignore in production)

`src/components/DevDebugPanel.tsx` only renders when `import.meta.env.DEV` is true (`npm run dev`). It does not appear in production builds.

## Hosting / base path

Non-Vercel builds use base path `/3Care/chi/gamify/pet_game/` (see `vite.config.ts`). Static assets and built JS/CSS must be served under that path unless you change `base` before building.
